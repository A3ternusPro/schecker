ГЕНЕРАТОР ROBOTS.TXT
Все проверки robots.txt собраны в один пункт технического блока.
Что проверять — в справке этого пункта, кнопка «?». Там же разбор
спецсимволов и приоритета правил.

В самом пункте: выбор системы управления сайтом, наборы «что закрыть
дополнительно», свои правила, Clean-param, адрес карты сайта — и готовый
файл с предупреждениями об ошибках.

Собирается так: секция для всех роботов, затем секция для Яндекса
с Clean-param, затем Sitemap одной строкой в конце. Повторы внутри
секции убираются, совпадения между секциями сохраняются.

Адрес карты сайта подставляется из домена проекта. Своё значение
в поле перебивает автоподстановку, пустое поле возвращает её.

Рядом с кнопками копирования и скачивания — ссылка на инструмент
анализа robots.txt в Яндекс.Вебмастере. После замены файла на сайте
проверьте там выборочно ключевые адреса.

ИМПОРТ SCREAMING FROG
Кнопка «Импорт SF» в шапке. Выгрузите в формате CSV:
  Internal → All — опорный файл
  All Inlinks по адресам с кодом ответа не 200 — источники ссылок

Поддерживается и массовый экспорт: Bulk Export → Issues → All.
Выберите все файлы папки разом — каждый опознаётся автоматически,
лишнее игнорируется. Набор файлов меняется от сайта к сайту, потому
что файл создаётся только для найденной проблемы: жёсткого списка нет.

Формат определяется сам: разделителем может быть запятая, точка
с запятой или табуляция, кодировкой — UTF-8 или windows-1251.
Файлы, пересохранённые через конвертер или Excel, тоже подойдут.

Файл определяется по имени, а при незнакомом имени — по колонкам.
Если заголовки изменились с новой версией Screaming Frog, чекер
предложит сопоставить колонки вручную, и выбор запомнится.

Под пунктами, где что-то найдено, появляется сводка и кнопка
копирования таблицы с русскими заголовками для Google Таблиц.

Сводка учитывает повторяемость: если одна ссылка встречается на ста
страницах, в ТЗ будет написано, что правка выполняется один раз
в шаблоне, а не что нужно исправить сто ссылок.

Порог значимости: пункт отмечается автоматически от трёх находок
либо от 0,5% страниц. Ваши ручные отметки не перезаписываются.

ГЕНЕРАЦИЯ ТЗ
Отметьте пункт как ошибку — под ним появятся поля переменных: сколько
страниц, ссылка на таблицу и так далее. В выгрузку попадёт готовая
задача: заголовок, «Задача», факты с вашими цифрами, «На что влияет»
из словаря аргументации, список «Что нужно сделать» и ссылка на таблицу.

Незаполненная переменная не ломает текст: предложение, где она стоит,
просто не попадает в документ.

ЧТО ПОПАДАЕТ В ТЗ
  Пункт с шаблоном  → полная задача с аргументацией
  Пункт в library   → описание блока или страницы
  Остальные         → краткая задача с вашим комментарием

Если два и более пункта одной группы отмечены как ошибка, они
собираются в одну задачу с общей аргументацией.

Перед задачами раздела GEO выводится вводный абзац: он честно
оговаривает, что рекомендации не гарантируют попадания в ответы ИИ.

АДМИНКА
Откройте admin.html, чтобы менять тексты проверок, заголовки задач,
формулировки аргументации и описания блоков — без правки файлов.
Там же конструктор тем оформления.

Правки пишутся в overrides.js, который накрывает базу и не затирается
при обновлении остальных файлов.

ВАЖНО ПРО СОХРАНЕНИЕ
Автосохранение работает в скачанном файле. При предпросмотре внутри чата
браузерное хранилище недоступно — сохраняйтесь кнопкой «Сохранить файл».
Файл .json — основной способ архива и передачи коллеге.

ПРО ЮРИДИЧЕСКИЕ ПУНКТЫ
Справка по 152-ФЗ, медицине, финансам и рекламе даёт ориентиры и ссылки
на нормы, а не юридическое заключение. Перед внесением в ТЗ для клиента
сверяйте с юристом.

ПРО РАЗДЕЛ GEO
Область меняется быстро: состав роботов ИИ, поддержка протоколов и
требования сервисов пересматриваются чаще классических факторов.
Проверяйте актуальность раз в квартал.
