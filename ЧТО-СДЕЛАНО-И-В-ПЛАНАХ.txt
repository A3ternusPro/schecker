ЧТО СДЕЛАНО
════════════════════════════════════════════════════════════

КОНФИГУРАТОР

Семь осей: тип сайта, модель продаж, отрасль, география,
поисковики, что есть на сайте, разделы аудита. Плюс 11
пресетов быстрого старта — от «интернет-магазин» до
«медицинская клиника».

У каждого варианта ответа счётчик влияния: видно, сколько
пунктов он добавит или уберёт. Пересчёт на лету.

Движок тегов: пункт показывается по условиям «любой из»,
«все из», «кроме». Есть производные теги — например,
регулируемая отрасль включается сама от выбора ниши.


ЧЕК-ЛИСТ

345 проверок, девять разделов:
технические правки, коммерческие элементы, блоки, страницы,
аналитика, доверие и E-E-A-T, юридические требования,
локальное SEO, GEO (нейропоиск).

На каждый пункт: статус (ок / ошибка / неприменимо),
заметка, приоритет. Можно добавлять свои пункты. Можно
отметить весь блок как неприменимый одной кнопкой.

Фильтры: не проверено, ошибки, критичные, критичные и
важные, с комментарием. Поиск по текстам и справке с
подсветкой совпадений.

Под шапкой полоса из 345 засечек — весь аудит целиком,
окрашено по статусам. Клик прокручивает к пункту.


СПРАВКА

345 записей, по одной на каждый пункт. Открывается столбцом
справа, может следовать за текущим пунктом.

Содержит: зачем это нужно, как проверять, чем проверять,
на что обратить внимание, когда это ложное срабатывание,
какая норма, как исправлять, синтаксис (где применимо),
связанные пункты.

Юридические, медицинские и финансовые формулировки — это
ориентир, а не юридическая консультация. Перед передачей
клиенту проверять с юристом.


ГЕНЕРАЦИЯ ТЗ

Выгрузка идёт только по пунктам со статусом «ошибка».
Три уровня качества текста:

  есть шаблон         → полная карточка с аргументацией
  есть описание в
  библиотеке          → структура блока или страницы
  нет ни того, ни
  другого             → задача текстом пункта и заметкой

Пункты можно объединять в одну задачу — например, все
проверки по зеркалам идут одной.

Цены по пунктам не выводятся. Приоритеты в документ тоже
не идут — они только для работы в интерфейсе.

Форматы выгрузки:
  — ТЗ в буфер как форматированный HTML (вставка в Google Docs)
  — ТЗ в файл .md
  — полный чек-лист в .md
  — таблица задач в TSV (вставка в Google Sheets)
  — файл проекта .json
  — печать в PDF


ГЕНЕРАТОР ROBOTS.TXT

Собирает файл по конфигурации: 10 пресетов CMS (Битрикс,
WordPress, OpenCart, ModX, Joomla, Tilda и другие), 7
функциональных наборов (корзина, поиск, личный кабинет,
фильтры, сортировки, печать, UTM), 24 правила по типам
ресурсов.

Структура результата: User-agent: * → User-agent: Yandex
с Clean-param → одна строка Sitemap в конце.

Проверка готового файла: 8 видов ошибок, включая
противоречия — когда один и тот же параметр закрыт в
Disallow и одновременно указан в Clean-param, или когда
закрыта пагинация.


ИМПОРТ SCREAMING FROG

Загружаются выгрузки, чекер сам ставит статусы и
подставляет цифры в формулировки ТЗ.

Опознаётся 53 типа файлов по имени — имя важнее заголовков,
потому что у пяти файлов с заголовками безопасности
заголовки колонок совпадают до байта.

Устойчивость к формату: определение разделителя (запятая,
точка с запятой, табуляция — с учётом кавычек), определение
кодировки (UTF-8, при неудаче windows-1251). Для каждой
колонки список синонимов на русском и английском, так что
смена версии SF или локализации не ломает разбор. Если
колонка не опознана — одно окно сопоставления, маппинг
сохраняется в файл проекта.

22 правила разбора. Строки с кодом ответа 0 исключаются —
это закрытые в robots.txt адреса, их никто не запрашивал.
Фильтрация по типу содержимого: 990 строк выгрузки могут
быть 127 страницами и 863 картинками.

Сквозные ссылки определяются по доле повторений, а не по
колонке Link Position — она врёт: сквозная кнопка в реальной
выгрузке была отмечена как Content.

Таблицы для исполнителя — с русскими заголовками: «где
располагается ссылка», «ссылка с ошибкой», а не Source и
Destination. Два варианта: уникальные ссылки и полный
список вхождений.

Формулировки в ТЗ согласуются по числу: «найдена одна
ссылка», «найдено 47 ссылок», с правильными падежами.


ОФОРМЛЕНИЕ

Шесть тем плюс «как в системе». Светлые: Бумага, Холст,
Контраст. Тёмные: Графит, Ночной синий, Уголь. Выбор темы
хранится отдельно от проекта — чужой файл не перебьёт
настройку.

Вид — «ревизорский бланк»: без скруглений, волосяные
линии, строки вместо карточек. Шрифт Golos Text — кириллица
спроектирована, а не адаптирована; IBM Plex Mono для цифр
и слагов.

Логотип: AETERNUS, под ним SEO AUDIT меньшим кеглем,
разделено линией, без анимации. Внизу — developed by
Alexander Kurbatov.


МОБИЛЬНАЯ ВЕРСИЯ

Блоки сворачиваются в аккордеоны, при поиске раскрываются
принудительно. Шапка не вылезает за экран, меню выгрузки
не уезжает за левый край, список прокручивается.


СОХРАННОСТЬ ДАННЫХ

Три уровня хранения с проверкой доступности при старте.
Автосохранение через 1,5 секунды после правки, индикатор
в шапке, восстановление незавершённого аудита при открытии,
предупреждение при закрытии вкладки.

Пункт с незнакомым слагом не теряется — уходит в «сироты»
вместе с данными. Слаги существующих пунктов никогда не
меняются и не переиспользуются: иначе старые аудиты
развалятся.

При запуске проверяется целостность разметки: если
какого-то узла нет, приложение говорит об этом, а не
работает молча наполовину.


АДМИНКА

Отдельный файл admin.html. Правит тексты пунктов,
подсказки, карточки ТЗ, справку, аргументацию. Результат
сохраняется в overrides.js — слой поверх базы, базовые
файлы не трогаются, обновление базы правки не затирает.

Там же можно добавить свою тему.

Правило: либо всё через админку, либо всё в файлах. Одно
и то же в двух местах править нельзя.

ЧТО В ПЛАНАХ

1. ЗАГРУЗКА ПАПКИ ЦЕЛИКОМ                     следующий шаг

   Сейчас файлы выгрузки выбираются по одному. Будет: указать
   одну папку, чекер сам возьмёт нужное.

   Главное здесь не выбор папки, а отбор ДО чтения. В папке
   массового экспорта бывает больше сотни мегабайт, и половина
   данных в ТЗ не попадёт. Имена файлов известны заранее,
   значит ненужные не открываются вовсе: 50 файлов превращаются
   в 15.

   Три уровня значимости:

     первый     ставит статус автоматически — редиректы, битые
                ссылки, дубли и пустые метатеги, один H1,
                канонические адреса, точные дубли, тонкий
                контент, вес картинок, незащищённый протокол

     второй     показывает сводку без статуса, решает
                специалист — alt-атрибуты, ссылки без анкора,
                заголовки безопасности, подчёркивания и
                регистр в адресах, параметры

     третий     не читается вовсе — длины title и description,
                пиксельные варианты, структура подзаголовков.
                Это рекомендации, а не ошибки, и автостатус по
                ним создаёт шум, который вытесняет настоящие
                проблемы

   Отчёт после разбора покажет не только что прочитано, но и
   что пропущено и почему — чтобы было видно, что данные не
   потерялись, а отобраны осознанно.

   Защита: файл больше 50 МБ пропускается с советом
   отфильтровать выгрузку в самом краулере; файл в формате
   Excel — с указанием переключить экспорт на CSV.


2. ИЗОБРАЖЕНИЯ В УСТАРЕВШИХ ФОРМАТАХ

   Новое правило: сколько картинок в старых форматах, сколько
   они весят, какая доля от общего веса изображений.

   В выгрузке Screaming Frog этого нет вообще — считается по
   общему обходу Internal → All, где есть тип содержимого и
   размер в байтах. Для ТЗ это конкретная цифра вместо
   расплывчатого «оптимизировать изображения».


3. DOCS.HTML — ИНТЕРАКТИВНАЯ ДОКУМЕНТАЦИЯ

   Руководство по главам в одном файле: конфигуратор, работа
   с чек-листом, справка, генерация ТЗ, robots.txt, импорт
   выгрузок, админка, правка файлов вручную. Заменит три
   текстовых файла инструкций.


4. API СКОРОСТИ

   Полевые показатели Core Web Vitals по кнопке: реальные
   данные пользователей вместо лабораторных. Закрывает
   несколько пунктов блока скорости автоматически.


5. ЗАКЛАДКА-СБОРЩИК

   Кнопка в браузере, которая собирает со страницы клиента
   то, чего нет в краулере: фактическое наличие блоков,
   микроразметка в отрендеренном виде, счётчики аналитики,
   поведение форм. Из 345 проверок так можно закрыть около 78.


6. ПРОЧЕЕ, БЕЗ СРОКОВ

   — таблица сопоставления колонок в админке
   — добавление пунктов через админку (сейчас только в db.js)
   — режим сравнения аудитов (поле prev в схеме уже есть)
   — расширение отраслевой базы за пределы медицины,
     финансов и юриспруденции

ЧТО СТОИТ ПРОВЕРИТЬ ПРИ ТЕСТЕ
════════════════════════════════════════════════════════════

1. Вставку ТЗ в Google Docs — сохраняются ли заголовки,
   жирный шрифт, списки.

2. Вставку таблицы задач в Google Sheets — раскладывается
   ли по столбцам сама.

3. Автосохранение: закрыть вкладку на середине аудита и
   открыть заново.

4. Импорт выгрузки Screaming Frog на реальном проекте —
   правильно ли расставлены статусы и совпадают ли цифры.

5. Мобильную версию на настоящем телефоне — до сих пор
   проверялась только эмуляцией.

6. Полный проход по живому сайту — станет видно, чего не
   хватает в базе и что мешает в интерфейсе.
